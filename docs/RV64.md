# RV64 and LP64

Select **RV64I / LP64** or **RV64IM / LP64** in the ISA control. The adjacent
extensions dialog offers M, A, F, D, C, Zicsr, Zba/Zbb/Zbc/Zbs, Zifencei and Zve32x/Zve32f with VLEN32/64/128. **New project → 64-bit values (RV64)**
prepares an example with values larger than 32 bits and useful watch expressions.
RV32 remains the default; architecture changes apply on the next build/load.

## Current scope

- RV64I base integer instructions and the M extension, including 32-bit word
  operations with architectural sign extension. Natural memory alignment,
  precise faults, x0, aliasing of input/output registers and 64-bit addresses.
- RV64 Teaching environment with the same console, LEDs/buttons, UART and
  framebuffer services. Pointer arguments are range checked before narrowing
  to bounded simulated RAM. An error result uses all XLEN bits set.
- GCC and Clang C/Assembly compilation with **LP64** and compatible GNU libgcc.
  `int` is 32 bits; `long`, pointers and integer registers are 64 bits.
- ELF64 loading with bounded segment/section offsets, architecture attributes,
  source/symbol metadata and 64-bit DWARF values, pointers and call frames.
- Register editing, 8-byte memory editing, conditions, watches, Back/Replay,
  saved future history and portable project restoration retain complete values.
- GDB target description and packets use 64-bit integer registers and PC;
  read/write watchpoints cover `ld`, `lwu` and `sd`.
- The instruction lab selects RV32/RV64 explicitly. RV64 shifts accept 0–63;
  `*w` shifts retain the five-bit shift amount.

RV64 now supports compressed instructions (including the RV64-specific word and
64-bit memory forms), the full A word/doubleword group, all four Zb bit groups, wide Zicsr registers,
M-only firmware with interrupts, and Zve32x with VLEN=32/64/128 and ELEN=32. Firmware keeps
the selected XLEN and adds Zicsr when needed. F and D, including full-width integer conversions, are available with
Zicsr; see `FLOATING_POINT.md`. Zve32f adds binary32 vector operations with
VLEN32/64/128 with ELEN32; ELEN=64 is not advertised.
Build profile changes do not replace an already loaded machine.

Scalar static analysis, readable C reconstruction and runnable C export support
RV64. The public C runtime preserves full-width registers, CSRs, atomics, memory
and firmware state, with an explicit LP64 native-call API. See `LINKED_C.md`.
Zve32x/Zve32f and multi-hart C export are also available. Full V remains pending. Native source/Assembly
debugging and raw/ELF/Assembly-image exports remain available. Guest RAM stays
bounded to 256 MiB; a large address traps instead of aliasing its low 32 bits.

## Expressions and reports

Expressions use the loaded machine's XLEN, including wrapping arithmetic,
signed `slt(a,b)`, bitwise operations and shifts. `u64(address)` reads eight
bytes in either XLEN and promotes its arithmetic to 64 bits; `u8`, `u16` and `u32` retain their explicit widths. Unary `*`
reads an XLEN-sized value. Literals up to UINT64_MAX are accepted; values wider than XLEN promote their
expression to 64 bits. Shifts must be below the left operand width.

Older scalar RV32 batch JSON keeps version 1. RV64 JSON uses version 2 or later
and `xlen: 64`; D uses version 4 with string-valued 64-bit floating registers.
PC, integer registers, trap values and expression observations are decimal
strings, preserving values beyond JSON consumers' 53-bit numeric precision.
Projects also save these values as strings. Teaching exit status remains a
32-bit status; the operating-system process exit status uses its low byte.

## Commands

To inspect an RV64 ELF from the extracted Linux package, run the classic CLI from its folder. Replace `program.elf` with your file and `result` with a symbol from that program.

```sh
./riscv32-studio --elf program.elf --ram 64KiB --run --json --observe result
```

The historical executable/project names retain `riscv32`/`.rv32project` for
compatibility; the saved architecture selects the actual machine width.

## Instruction extensions

See [atomic operations](ATOMICS.md), [firmware](FIRMWARE.md) and [vectors](VECTORS.md) for profile-specific instructions and limits.

RV64 Zba/Zbb/Zbc/Zbs includes 43 operations: 32 XLEN-wide forms plus the
11 RV64 word/unsigned-word forms. Zext.h and rev8 use the RV64 encodings;
common immediate bit operations accept 0..63. See `BITMANIP.md`.
